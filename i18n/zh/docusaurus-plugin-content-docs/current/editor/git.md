title: Git 版本控制
sidebar_position: 22
---

RemixWarp 在编辑器中内置了完整的 Git 版本控制系统。它跟踪项目的历史，让您可以提交快照、回顾更改、在分支上工作并推送到托管仓库。整个仓库（包括其历史）**位于项目文件内部**，因此它随 `.sb3` 一起旅行。

版本控制适合较大或长期的项目，它是通过拉取请求而不是实时编辑进行协作的基础。

## 打开版本控制

打开**工具**菜单并选择**Git**，这会打开**版本控制**窗口。左侧的侧边栏在更改、历史、分支、差异、远程、Rotur Git 和自述文件之间切换。

如果项目尚未受版本控制，您会得到**初始化仓库**选项来开始一个，或一个通过 URL **克隆**现有项目的字段。

## 提交更改

**更改**视图列出自上次提交以来每个更改过的文件，每个都标有状态：已修改、已添加或已删除。编写描述更改的消息并点击**提交**。**撤销上次提交**反转最近的一次。点击更改的文件会打开它的差异。

您也可以让 RemixWarp 在每次保存时替您提交：在**版本控制**[设置](/user-guide/settings)页面上打开**保存项目时自动提交**，您还可以在那里设置提交作者名称和电子邮件。

## 历史与差异

**历史**列出您的提交，每个都有消息、短哈希和颜色编码的分支图。选择提交可以看到它更改的文件、将项目恢复到它，或将其下载为 `.sb3`。

**差异**显示您的工作更改与上次提交之间的可读逐行比较。因为 RemixWarp 比较的是项目的文本表示而不是原始 JSON，添加和删除是清晰的：您实际上可以读到脚本中发生了什么变化。

## 分支与合并

**分支**让您创建、切换和删除分支，这样您可以在不干扰主线的情况下开发功能。要合并分支，选择一个源分支并**预览**合并。

如果合并有冲突，RemixWarp 会列出每个冲突文件，并要求您为每个选择一方，**我们**或**他们**，然后**应用合并**。对于更复杂的情况，**在编辑器中解决**会用常见的冲突标记打开代码编辑器中的冲突文件，让您手动解决。

## 远程与托管

**远程**管理通用的 Git 远程仓库（例如 GitHub 仓库）：用 URL 和访问令牌添加远程仓库，然后向其推送分支。

**Rotur Git** 是内置的托管后端，运行在 git.rotur.dev 上。当您用[Rotur 账户](/getting-started/introduction)登录时，您可以创建仓库、直接从编辑器推送项目、克隆任何 Rotur 仓库，而无需设置单独的访问令牌。仓库可以是公开的或私有的。没有单独配置凭据的步骤：使用您的 Rotur 登录。

**自述文件**编辑项目的 README，它存储在仓库中并随其他所有内容一起在 `.sb3` 内旅行。
