# 沙箱是什麼

有兩種自定義擴展：**沙箱**和**非沙箱**。到目前為止的一切都是沙箱的。本頁解釋這意味著什麼，以及為什麼您通常會想要另一種。

## 沙箱

在 RemixWarp 中，沙箱是一個 `<iframe>`。沙箱擴展運行在無法觸及編輯器和 VM 所在主頁面上的跨源 iframe 中。它被隔離在自己的世界中。

這種隔離意味著沙箱擴展：

- 不能訪問 RemixWarp 內部（VM、運行時、渲染器）
- 不能讀取項目中未作為參數傳遞給它的任何部分，包括變量
- 不能直接與角色交互

它仍然可以：

- 調用大多數公共 Web API，受 [CORS](https://developer.mozilla.org/zh-CN/docs/Web/HTTP/CORS) 約束
- 使用許多不需要頁面訪問的瀏覽器 API，例如 [Gamepad API](https://developer.mozilla.org/zh-CN/docs/Web/API/Gamepad_API/Using_the_Gamepad_API)

其他一些 Scratch 修改版在 `Worker` 中沙箱擴展。RemixWarp 使用 iframe，因為它是跨源的（更安全）並暴露更多 Web API。

## 大限制

每次沙箱積木運行時，腳本至少暫停一幀，無論積木多麼微不足道。"運行時不刷新屏幕"和渦輪模式都不會改變這一點；等待是不可避免的，因為每次調用都必須跨越 iframe 邊界。

每個積木一幀的成本使沙箱擴展對任何在循環中運行的東西幾乎無用，這就是非沙箱擴展存在的原因。

## 非沙箱擴展

非沙箱擴展不在 iframe 中運行。它與 RemixWarp 本身在同一頁面上運行，作為 `<script>` 標籤加載。因此它：

- **可以**訪問 RemixWarp 內部
- **可以**讀取項目的任何部分，包括變量
- **可以**直接與任何角色交互

並且，關鍵是，運行它的積木是瞬時的。沒有強制的一幀延遲。

權衡是信任和責任：因為非沙箱代碼可以做頁面能做的任何事情，RemixWarp 只在特定條件下以非沙箱方式運行它，而您要承擔一些額外的規則。這是[下一頁](/extensions/unsandboxed)的主題。

## 練習

1. 加載一個帶什麼都不做的 `COMMAND` 積木的沙箱擴展（就像您一直在做的）。在一個空項目中，把它放進 `重複執行 (10)` 四次。注意循環花費超過一秒，儘管積木什麼都沒做。
2. 用 `將我的變量設為 0` 替換那些積木。循環現在立即完成。這就是非沙箱擴展積木的行為方式。
3. 在沙箱擴展內部，`console.log(window.origin)`。與在主頁面控制台中輸入的 `window.origin` 比較。它們不同，因為沙箱是一個獨立的源。
