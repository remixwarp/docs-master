title: Git 版本控制

RemixWarp 在編輯器中內置了完整的 Git 版本控制系統。它跟蹤項目的歷史，讓您可以提交快照、回顧更改、在分支上工作並推送到託管倉庫。整個倉庫（包括其歷史）**位於項目文件內部**，因此它隨 `.sb3` 一起旅行。

版本控制適合較大或長期的項目，它是通過拉取請求而不是實時編輯進行協作的基礎。

## 打開版本控制

打開**工具**菜單並選擇**Git**，這會打開**版本控制**窗口。左側的側邊欄在更改、歷史、分支、差異、遠程、Rotur Git 和自述文件之間切換。

如果項目尚未受版本控制，您會得到**初始化倉庫**選項來開始一個，或一個通過 URL **克隆**現有項目的字段。

## 提交更改

**更改**視圖列出自上次提交以來每個更改過的文件，每個都標有狀態：已修改、已添加或已刪除。編寫描述更改的消息並點擊**提交**。**撤銷上次提交**反轉最近的一次。點擊更改的文件會打開它的差異。

您也可以讓 RemixWarp 在每次保存時替您提交：在**版本控制**[設置](/editor/settings)頁面上打開**保存項目時自動提交**，您還可以在那裡設置提交作者名稱和電子郵件。

## 歷史與差異

**歷史**列出您的提交，每個都有消息、短哈希和顏色編碼的分支圖。選擇提交可以看到它更改的文件、將項目恢復到它，或將其下載為 `.sb3`。

**差異**顯示您的工作更改與上次提交之間的可讀逐行比較。因為 RemixWarp 比較的是項目的文本表示而不是原始 JSON，添加和刪除是清晰的：您實際上可以讀到腳本中發生了什麼變化。

## 分支與合併

**分支**讓您創建、切換和刪除分支，這樣您可以在不干擾主線的情況下開發功能。要合併分支，選擇一個源分支並**預覽**合併。

如果合併有衝突，RemixWarp 會列出每個衝突文件，並要求您為每個選擇一方，**我們**或**他們**，然後**應用合併**。對於更復雜的情況，**在編輯器中解決**會用常見的衝突標記打開代碼編輯器中的衝突文件，讓您手動解決。

## 遠程與託管

**遠程**管理通用的 Git 遠程倉庫（例如 GitHub 倉庫）：用 URL 和訪問令牌添加遠程倉庫，然後向其推送分支。

**Rotur Git** 是內置的託管後端，運行在 git.rotur.dev 上。當您用[Rotur 賬戶](/getting-started/introduction)登錄時，您可以創建倉庫、直接從編輯器推送項目、克隆任何 Rotur 倉庫，而無需設置單獨的訪問令牌。倉庫可以是公開的或私有的。沒有單獨配置憑據的步驟：使用您的 Rotur 登錄。

**自述文件**編輯項目的 README，它存儲在倉庫中並隨其他所有內容一起在 `.sb3` 內旅行。
